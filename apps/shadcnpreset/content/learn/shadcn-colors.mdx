Every shadcn/ui component gets its colors from a small set of CSS variables.
Change the variables and every component changes with them, without touching the component code.
That's what makes [themes](/themes) and [presets](/learn/what-is-a-shadcn-preset) work.

This article covers how those variables work, why their values are written in OKLCH, how shadcn builds its own color themes, and how to bring in a color of your own.

## How shadcn colors work

When you set up shadcn/ui, your global CSS gets a block of color variables for light mode and another for dark mode:

```css
:root {
  --background: oklch(1 0 0);
  --foreground: oklch(0.145 0 0);
  --primary: oklch(0.205 0 0);
  --primary-foreground: oklch(0.985 0 0);
  --border: oklch(0.922 0 0);
  /* …card, popover, secondary, muted, accent, destructive, input, ring, charts, sidebar */
}

.dark {
  --background: oklch(0.145 0 0);
  --foreground: oklch(0.985 0 0);
  /* …the same names, dark values */
}
```

Tailwind turns each variable into a color you can use in classes, so components are written with names, not values:

```css
@theme inline {
  --color-background: var(--background);
  --color-primary: var(--primary);
  --color-muted-foreground: var(--muted-foreground);
}
```

```tsx
<button className="bg-primary text-primary-foreground">Save</button>
```

A preset decides what those values are.
The **base color** (neutral, stone, zinc, mauve, olive, mist or taupe) sets the greys: background, borders, muted text.
The **theme** sets the accent: primary buttons, focus rings and highlights.
**Chart colors** and **radius** sit alongside them.

## Why the values are in OKLCH

Every value is written as `oklch(lightness chroma hue)`. The format separates three properties of a color:

- **Lightness** runs from 0 (black) to 1 (white).
- **Chroma** is how colorful it is. 0 is grey. The most vivid colors reach about 0.32 on a standard (sRGB) screen, and about 0.36 on a wide-gamut (Display P3) screen, like most recent Macs and phones.
- **Hue** is its angle around the color wheel, from 0 to 360: about 25 is red, 145 green and 255 blue.

OKLCH makes it easier to build palettes where colors have a consistent perceived lightness. That's because it separates lightness, chroma and hue, so you can adjust one without deliberately changing the others.

This is something older formats like HSL struggle with. Two colors can both have 50% lightness in HSL but look very different. Yellow looks much brighter than blue, even though their numbers are the same.

The comparison below shows the difference. Both rows use the same lightness value, but the numbers underneath reveal how differently HSL colors actually appear when measured in OKLCH.

You'll also notice that some OKLCH colors reach their maximum chroma before others.
Not every hue can be displayed at the same saturation and lightness. The limit depends on your display, with wide-gamut screens able to show more vivid colors than standard sRGB screens.

For theming, this makes it easier to build palettes with a consistent visual balance.

Changing a primary color from blue to orange doesn't mean starting from scratch. You can keep the lightness consistent and adjust the hue, then check the resulting contrast. Lightness helps, but contrast still depends on both the foreground and background colors.

The [color contrast checker](/tools/color-contrast-checker) lets you check a pair of values.

### How base colors work

A base color is a set of greys with a slight hint of hue: very low chroma, pointed towards a warm or cool part of the color wheel.

That's the only difference between neutral, mist, mauve, taupe and olive.

## How shadcn builds its color themes

shadcn ships 17 colored themes, from amber to yellow, and they follow a clear pattern.

### Mid-tone accents with light text
15 of the 17 put their primary between 0.46 and 0.56 lightness, with near-white text tinted slightly towards the same hue. Every one passes 4.5:1 text contrast, from 4.8:1 (green) to 7.2:1 (indigo).

### Light accents get dark text
Lime and yellow are the exceptions. Their primaries sit at about 0.85 lightness, too light for white text, so they use a dark text color instead.

### Dark mode keeps the hue
The dark primary stays within a few degrees of the light one, about 0.07 darker, with around 82% of the chroma. The text color doesn't change, so contrast goes up: 6.8:1 to 9:1 for the mid-tone themes.

<OklchShowcase variant="primaries" caption="The primary from four of shadcn's themes, with the text color each one uses. Blue, orange and green take light text and get darker in dark mode. Yellow is light enough to need dark text." />

The base colors work differently.
In neutral, stone, zinc and the rest, the primary is a near-black grey that flips to a near-white grey in dark mode.

## Using your own color

Brand colors rarely land on one of shadcn's, and you don't need to work out the rest of the palette by hand.
Pick your color below and the theme generator will create an entire theme, light and dark, that you can open as a preset or copy as CSS.

<OklchShowcase variant="brand" caption="Drag in the picker or paste any CSS color. This runs the same code as the customise panel on our preset pages. Switch the site to dark mode to see the dark values, and try the orange, yellow and dark indigo examples." />

It makes the same decisions shadcn's own themes make:

### Choosing text that stays readable

White text works well on colours up to around 0.55 lightness, which is why shadcn's mid-tone themes tend to stop around 0.56. Once you get above 0.6, dark text usually becomes the better choice. You can see this in the lime and yellow examples.

The generator compares both and picks whichever gives better contrast. That's why orange and yellow use dark text. There’s a tricky range between 0.55 and 0.6 where neither may meet the 4.5:1 contrast target. If the contrast figure drops below that, try adjusting the lightness.

### Building the rest of the palette

The ring, sidebar and chart colours aren't just variations of your main colour. The generator starts with the closest shadcn theme, shifts its hue to match yours, and keeps the lightness suited to each colour's role.

### Keeping your colour recognisable in dark mode

Shadcn darkens its primary colours for dark mode. That works for its own palettes, but can make a brand colour harder to recognise. The generator keeps your chosen colour closer to its original appearance, only lightening it when needed to stand out against the dark background, as with the dark indigo example.

### Adding a tint to your greys

A base colour gives the greys in your palette a subtle hint of hue. You can take this a step further by switching on tinting, which carries that hue into muted text and borders too. The chroma stays very low, so they still look grey rather than coloured.

It's most noticeable with stronger hues like yellow. Whether you use it comes down to the look you're after.

## Conclusion

Shadcn's theming works because components read their colors from CSS variables rather than hard-coded values. Change the variables and every component built on those tokens follows along.

OKLCH makes those colors easier to build and adjust. By separating lightness, chroma and hue, you can create palettes around your own brand colors without starting from scratch.

The quickest way to get started is with the picker above. Choose a color, open it as a preset and install it with the shadcn CLI. Or start with one of the [shadcn color themes](/themes), or [generate a preset with AI](/assistant).
