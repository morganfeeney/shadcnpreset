Last week I asked Claude how to find shadcn presets. It sent me to Tweakcn.

Tweakcn is a good tool. It's a theme editor: you move sliders, it gives you CSS variables. But I hadn't asked for a theme editor. I wanted to browse presets other people had already put together and pick one. The answer came back wrong because "theme" and "preset" get used as if they mean the same thing, and they don't.

So here's the distinction as plainly as I can put it.

## A preset is a code

A shadcn preset is a short code like `b4YtS7GakV`. Presets arrived with shadcn/ui v4 and [shadcn create](https://ui.shadcn.com/create): you pick options in the builder, and the current combination gets encoded into that code. You can hand it straight to the CLI.

```bash
# New project
npx shadcn@latest init --preset b4YtS7GakV

# Existing project
npx shadcn@latest apply --preset b4YtS7GakV
```

To see what's in one, decode it:

```bash
npx shadcn@latest preset decode b4YtS7GakV
```

```
Preset
  code         b4YtS7GakV
  style        luma
  baseColor    mist
  theme        lime
  chartColor   indigo
  iconLibrary  tabler
  font         instrument-sans
  fontHeading  merriweather
  radius       large
  menuAccent   subtle
  menuColor    inverted-translucent
```

Ten fields. About half of them are colour, and could live in a theme file. The other half can't.

| Field | What it controls | Could a theme do it? |
| --- | --- | --- |
| `style` | Component shape: padding, height, type size, corners, focus rings. Vega, Nova, Maia, Lyra, Mira, Luma, Sera, Rhea. | No |
| `baseColor` | The neutrals: background, card, border, muted text | Yes |
| `theme` | The accent colour | Yes |
| `chartColor` | `--chart-1` to `--chart-5` | Yes |
| `radius` | The `--radius` variable | Yes |
| `menuAccent` | Grey or primary-coloured highlight on menu items | Yes |
| `menuColor` | Default or inverted, solid or translucent menus | No |
| `font` / `fontHeading` | Body and heading fonts, installed for you | No |
| `iconLibrary` | Lucide, Hugeicons, Tabler, Phosphor or Remix Icon | No |

One thing a preset doesn't decide: whether your components are built on Radix or Base UI. That's the separate `--base` flag on `init`, and the same code works with either.

## A theme is CSS variables

shadcn/ui components use classes like `bg-primary` and `border-border`. Those point at variables in your global CSS, with a light set and a dark set:

```css
:root {
  --radius: 0.625rem;
  --background: oklch(1 0 0);
  --primary: oklch(0.205 0 0);
  --border: oklch(0.922 0 0);
  /* ... */
}

.dark {
  --background: oklch(0.145 0 0);
  /* ... */
}
```

Change the values and everything recolours. That's the whole mechanism, and it's what theme generators produce, Tweakcn included. It's portable and low-risk, and if colour is all you want to change it's the right tool.

The limit is that variables can only change things the components already read from variables.

## Why the other half can't be CSS

`style` is the big one. It lives in the component classes. Lyra's base button has `rounded-none text-xs focus-visible:ring-1`. Maia's has `rounded-4xl text-sm focus-visible:ring-[3px]`. Same theme variables on both of these:

<StyleShowcase
  styles={["lyra", "maia"]}
  controls={["button", "input", "switch"]}
  baseColor="mist"
  theme="lime"
  radius="large"
  caption="Mist and lime, radius large, on Lyra and Maia. The CSS variables are identical; the components aren't."
/>

There is no variable you can set to turn one into the other; you need different component code. [I wrote up the styles separately](/learn/how-to-choose-a-shadcn-style) because it's the field that changes how a page feels the most, and the one a colour picker can't show you.

Fonts and icons are similar. Switching icon library changes the imports inside every component. Fonts get wired into your app with `next/font` or Fontsource. Menu colour changes the classes on dropdown and popover content.

That's why the CLI treats a full preset as a bigger operation than a theme. When you apply one, it tells you it "will overwrite existing UI components, fonts, and CSS variables" and lists the components it's about to reinstall. Pasting a theme never touches a component file.

## If you only want the colours

You can take part of a preset:

```bash
npx shadcn@latest apply --preset b4YtS7GakV --only theme
npx shadcn@latest apply --preset b4YtS7GakV --only font
```

Or paste the code into the [Preset Theme CSS Generator](/tools/preset-theme-generator) and copy the light and dark variables. Worth running it through the [contrast checker](/tools/color-contrast-checker) too. A preset's accent looks fine on a swatch and can still fail as button text.

## Where this leaves you

If you want to build a preset from scratch, [shadcn create](https://ui.shadcn.com/create) is the official place to do it.

If you want to recolour what you already have, a theme editor or the CSS generator above is the right tool.

If you want to look at presets that already exist and pick one, that's the gap I ran into, and it's what I built this site for. [Community](/community) is what people are voting for. [Ask AI](/assistant) takes a description of what you're building and shows matching presets on real components before you run anything.
